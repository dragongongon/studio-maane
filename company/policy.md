# スタジオまあね 会社方針

## 目的
AIを活用して、顧客がお金を払う価値のある商品・サービスを作り、継続的な収益を生み出す。

## 最初の目標
月1万円の継続収益を作る。制作物を増やすこと自体ではなく、顧客価値の発見・検証と実売上を優先する。

## 事業の優先順位
1. 売れる可能性と顧客の支払意思
2. 顧客にとっての価値
3. 継続的な収益性
4. 低い初期費用
5. 少ない人的作業
6. AIによる効率化・自動化
7. 制作・運営の容易さ

## 基本原則
- 「誰が、なぜ、お金を払うのか」を明確にする。
- 推測と確認済み情報を区別する。重要な判断では、可能な範囲で複数の情報源を比較する。
- 面白さやAI活用そのものを商品化の理由にしない。
- 無料の代替手段、競合、顧客の支払意思、制作・運営コストを確認する。
- 反応や売上などの実績を見て判断し、根拠なく成功を想定しない。
- 初期段階では無料または低コストのツールを優先する。費用が発生する判断は事前承認を得る。
- 過去の議論を繰り返さないよう、確定事項・却下事項・再検討しない事項をプロジェクト内に記録する。
- GitHub DiscussionsはAI同士・人間との議論を集約する場として使えるが、別サービス間で文脈が自動共有されるとは限らない。必要な前提・決定事項は明示的に渡す。

## 事業・コンテンツの整理
- 現在追跡するnote連載は、主に「AIが紡ぐ物語」と「AIと学ぶ技術」。
- 連載の進捗・次の行動はリポジトリ直下の `SERIES.md` で管理する。
- `products/` は個別企画の資料・成果物・履歴を保持する。プロダクト番号とnote記事番号は別管理とし、1つのプロダクトから複数の記事が生まれることもある。
- 過去のP01〜P15を含む既存企画は履歴として尊重し、整理目的だけで安易に改番・移動・削除しない。

## 承認が必要な事項
次の事項はオーナーの明示的な承認を得る。
- 実際の支払い、有料サービスの契約
- noteなどへの外部公開・販売開始
- 他者への連絡
- 法的・規約上のリスクを伴う判断
- 重要な会社方針やプロジェクト方針の変更

## 商品開発の基本フロー
市場・競合調査 → 顧客定義 → 課題定義 → 商品企画 → 価格仮説 → 小さな試作品 → 品質・リスク確認 → 販売方法の設計 → オーナー承認 → 公開・販売 → 反応・売上分析 → 改善。

すべての企画で全工程を機械的に実施するのではなく、記事など小さな実験では規模に応じて簡略化する。ただし、公開・販売前の承認は省略しない。
