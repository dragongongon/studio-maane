# AIで稼ぐ実験

## 目的
外部で語られるAI副業・note収益化の手法を、小さなサイクルで実行し、できた記事をnoteに公開するシリーズ。

「誰でも簡単に月○万円」系の主張をそのまま信奉せず、読者が「自分でも試す価値があるか」を判断できる材料を提供する。

**定義**：先に実験、後に検証。  
- **実験**：外部手法を小さく回し、記事にしてnoteへ公開すること（公開された記事そのものが実験）  
- **検証**：公開後、しばらくしてから閲覧・スキ・購入などの数字を見ること  
実験を設計／市場の二段階には分けない。売上がない段階を検証完了のように書かない。

**方針**：外部SNSでの定期告知を必須にしない。note内の露出を主な入口にし、「書く→公開→（しばらく後に）数字を見る→1点直す」を低負荷で回す。

役割の正本は `company/content-roles.md`。

## 進め方（2026-10-14）
- **GrokとMuseSparkの2ルートで進める。**
- **Grok**：手法の構造化・批判的評価・実験の型づくり。
- **MuseSpark**：SNS・公開情報から手法発見・出典確認・候補比較・実験計画・記事草稿。探索能力は調査品質で評価する。
- MuseSparkはGrokの既存実験を差別化なく繰り返さない。
- **「AIと学ぶ技術」とは別路線**。学ぶの反応・テーマ・公開順に依存しない。
- 次の記事は、本シリーズ自身の公開後数字と実験結果で決める。
- AIの優劣ランキングは作らない（好みの分岐・条件差は書いてよい）。

## 想定読者
- AI副業やnote有料記事に興味があるが、「また情報商材か」と疑っている人
- AIへの指示テンプレを試したが成果が出ず、何が足りないのか知りたい人
- 実績ゼロの状態から小さく実験したい人
- 毎日の告知作業なしで続けたい人

## 執筆方針
- 公開前の記事に、まだない売上数字を書かない。未測定は未測定と書く。
- 推測と確認済みを区別する。誇張した収益数字を出さない。
- 無料代替や競合の存在を明示する。
- 公開・有料販売はオーナー承認後。
- タイトル接頭語は「AIで稼ぐ実験」。
- 特定の発信者・製品への依存記事にしない（検証上必要な事実記載は可）。
- 調査のみで公開していない段階を、完了した実験結果のように書かない。
