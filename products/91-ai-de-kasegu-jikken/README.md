# AIで稼ぐ実験

## 目的
外部で語られるAI副業・note収益化の手法を、小さな実験として実行し、過程・数字・失敗を一次情報として公開するnoteシリーズ。

「誰でも簡単に月○万円」系の主張をそのまま信奉せず、読者が「自分でも試す価値があるか」を判断できる材料を提供する。

**定義**：先に実験、後に検証。  
- **A. 設計実験**：手法の分解、手順・ペルソナ・線引き・価格の組み立て  
- **B. 市場実験**：公開後の閲覧・スキ・購入などの数字  
公開前の記事を、売上実績の検証完了報告のように書かない。

**方針**：外部SNSでの定期告知を必須にしない。note内の露出を主な入口にし、「書く→公開→数字を見る→1点直す」を低負荷で回す。

役割の正本は `company/content-roles.md`。

## 進め方（2026-10-13）
- **GrokとMuseSparkの2ルートで進める。**
- **Grok**：手法の構造化・批判的評価・実験の型づくり。
- **MuseSpark**：SNS・公開情報から手法発見・出典確認・候補比較・実験計画・記事草稿。探索能力は調査品質で評価する。
- MuseSparkはGrokの既存実験を差別化なく繰り返さない。
- **「AIと学ぶ技術」とは別路線**。学ぶの反応・テーマ・公開順に依存しない。
- 次の記事は、本シリーズ自身の数字と実験結果で決める。
- AIの優劣ランキングは作らない（好みの分岐・条件差は書いてよい）。

## 想定読者
- AI副業やnote有料記事に興味があるが、「また情報商材か」と疑っている人
- AIへの指示テンプレを試したが成果が出ず、何が足りないのか知りたい人
- 実績ゼロの状態から小さく実験したい人
- 毎日の告知作業なしで続けたい人

## 執筆方針
- 設計実験と市場実験を混同しない。未測定は未測定と書く。
- 推測と確認済みを区別する。誇張した収益数字を出さない。
- 無料代替や競合の存在を明示する。
- 公開・有料販売はオーナー承認後。
- タイトル接頭語は「AIで稼ぐ実験」。
- 特定の発信者・製品への依存記事にしない（検証上必要な事実記載は可）。
- 調査のみの段階を「実験結果」と呼ばない。
