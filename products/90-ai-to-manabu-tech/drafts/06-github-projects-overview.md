# AIと学ぶ技術｜AIを使った副業の全体像をGitHub Projectsで見える化する

GitHub Issuesに作業を書き出すと、何をやるべきかを頭の中で覚え続けずに済みます。ただ、作業が増えてくると、今度は別の疑問が出てきます。

記事づくりは進んでいるけれど、商品企画は止まっていないか。調査ばかり増えて、実際に公開できるものができていないのではないか。技術的な改善に時間を使いすぎて、収益につながる作業が後回しになっていないか。

個々のタスクが見えていても、プロジェクト全体のバランスが分かるとは限りません。そこで、GitHub Projectsを使って、複数の作業を一覧で見渡す方法があります。

## Issueの一覧と、プロジェクト全体の見取り図は違う

GitHub Issuesは、個々の課題や作業項目を記録するのに向いています。一方、GitHub Projectsは、Issueなどをまとめ、状態や優先順位、分類などの観点から一覧化するために使えます。

例えば、AIを使った副業プロジェクトなら、次のような活動が並行して進むかもしれません。

- **企画・調査**：読者の課題、競合、商品候補を調べる
- **制作**：記事、テンプレート、Webサービスなどを作る
- **公開準備**：説明文、サムネイル、動作確認を行う
- **販売・改善**：反応や売上を確認し、次の改善を考える

個々のIssueを見ているだけだと、作業の数が多い領域ばかりに目が向くことがあります。Projectsで全体を見渡せば、どの領域に作業が集中しているか、何が止まっているかを把握しやすくなります。

## まずは状態が分かるボードを作る

最初から複雑な管理表を設計する必要はありません。まずは、作業の状態を見えるようにします。

例えば、次のような列を用意します。

- 未着手
- 作業中
- 確認待ち
- 完了

実際に使える状態や設定は、GitHub Projectsの機能や現在の設定に応じて調整してください。大切なのは、一覧を見たときに、各作業がどこで止まっているかを把握できることです。

Issueを作っただけでProjectsにも必ず自動登録されると考えず、必要なIssueがプロジェクトに追加されているか確認します。運用に慣れてから、追加方法やビューを調整すれば十分です。

## 「作業中」が多すぎないかを確認する

Projectsの価値は、作業を並べることだけではありません。今の進め方を振り返るきっかけにもなります。

例えば、未完了の作業が大量にある場合、次のような問いを立てられます。

- 同時に進める作業が多すぎないか
- 完了条件が曖昧で、終わりを決められないタスクはないか
- AIの提案を集めること自体が目的になっていないか
- 公開や顧客の反応確認より、準備ばかりを続けていないか
- 収益につながる仮説を検証する作業が入っているか

特に副業では、調査や改善に時間を使うだけで満足してしまう危険があります。ボードを見ながら、制作・公開準備・顧客の反応を確かめる作業が進んでいるかを確認すると、活動の偏りに気づきやすくなります。

ただし、Projectsが事業の優先順位を自動で決めてくれるわけではありません。何を優先するかは、目的や使える時間、顧客にとっての価値を踏まえて人間が判断します。

## AIとの作業も、全体の中に位置づける

AIに調査や執筆、レビューを頼むと、個々の作業は進んでいるように見えます。しかし、回答が増えても、商品や記事として完成していなければ、目標に近づいていないこともあります。

そこで、AIに依頼するタスクだけでなく、その成果を何に使うのかもIssueに記録します。

例えば「競合を調査する」というタスクなら、完了条件を「競合を5件挙げる」だけにするのではなく、「比較結果をまとめ、商品案を続けるか見送るか判断できる状態にする」と設定できます。

こうすれば、AIに作業を頼むことと、プロジェクトの成果を出すことをつなげやすくなります。Projectsでは、調査・制作・検証などの作業がどの段階にあるかを俯瞰できます。

もちろん、AIの成果物が正しいか、顧客に価値があるかは別途確認が必要です。タスクが「完了」になっていることと、事業上の成果が出たことを混同しないようにします。

## 管理のための管理を増やさない

Projectsを使い始めると、分類項目やビューを増やしたくなるかもしれません。しかし、入力や更新に時間がかかりすぎるなら本末転倒です。

まずは、次のことが分かれば十分です。

1. 今、何を進めているか
2. 何が止まっているか
3. 次に何をするか
4. プロジェクトの目的に近づいているか

必要になったら、優先順位や活動領域などの項目を追加します。毎回細かく更新するより、実際の作業判断に役立つ範囲で続けることを優先します。

GitHubを使っていない人なら、同じ考え方を表計算ソフトやタスク管理アプリで実現しても構いません。ツールをそろえることより、個々の作業と全体の進捗を分けて見られることが重要です。

## タスクを管理するだけでなく、成果につなげる

AIを使う副業では、できることが増える一方で、やりたいことや未完了の作業も増えがちです。Issuesで作業を外に書き出し、Projectsで全体を見渡すと、覚えておく負担を減らしながら、今どこに集中すべきか考えやすくなります。

最初から完璧な仕組みを作る必要はありません。まずは数件のIssueをボードに並べ、未着手・作業中・完了が分かるようにしてみてください。

そして、定期的にボードを眺め、「タスクは進んでいるか」だけでなく、「顧客に価値を届けることに近づいているか」を問い直します。

**全体を見えるようにする目的は、管理を増やすことではなく、限られた時間を大事な作業に使うこと**です。
