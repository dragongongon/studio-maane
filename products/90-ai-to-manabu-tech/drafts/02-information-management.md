# AIと学ぶ技術｜AIに毎回同じ説明をしないための情報整理術

複数の生成AIを使って、ひとつの企画や作品について何度も話し合う。

それぞれのAIから違った意見が出てくるのは便利です。けれど、議論が長くなると、こんなことが起こります。

- 以前に却下した案が、また提案される
- 決定済みの方針が、いつの間にか再検討される
- いま何を優先しているのか、AIに説明し直す
- 過去の会話を探すだけで時間がかかる

AIに何度も同じ説明をしていると、仕事が進んでいるのか、同じ場所を回っているのか分からなくなることがあります。

私が複数のAIと継続的に作業するなかで役立っているのは、**会話をすべて保存することより、次の判断に必要な情報を会話の外に整理しておくこと**です。

## 1. 会話の履歴と、今後も使う情報を分ける

チャットや議論の履歴には、検討中の案、質問、脱線、却下した案など、さまざまな情報が含まれます。履歴は経緯を振り返るには便利ですが、次の作業で必要な情報を毎回探すのは効率的ではありません。

そこで、情報を大きく二つに分けます。

- **議論の履歴**：どんな意見が出て、どう検討したか
- **作業の基準になる情報**：何を目指し、何が決まり、現在どこまで進んでいるか

GitHub Discussionsなどは前者に向いています。後者は、プロジェクトのファイルとして整理しておくと参照しやすくなります。

## 2. 最低限、4種類の情報を整理する

最初から大量の文書を作る必要はありません。まずは、次の役割を意識するだけでも整理しやすくなります。

### 目的・前提

プロジェクトの目的、想定読者、制約、守るべきルールをまとめます。何のために作業しているのかを毎回説明し直さずに済むようにするためです。

### 決定事項

採用した方針と、その理由を記録します。提案された段階の案と、正式に決まった内容を混同しないことが重要です。

### 再検討しない事項・禁止事項

却下した案や、変更しないと決めた前提を記録します。ただし「絶対に変えない」とするだけではなく、必要なら再検討できる条件も残します。

### 現在の状況

完了したこと、取り組み中のこと、未解決の課題、次に行うことをまとめます。これが古いままだと、AIがすでに終わった作業を提案したり、状況を取り違えたりする原因になります。

ファイル名は自由です。例えば `PROJECT.md`、`DECISIONS.md`、`NOT_TO_REVISIT.md`、`STATUS.md` のように分けられます。小さな企画なら、ひとつのファイルから始めても構いません。

## 3. 「却下した案」には理由も残す

例えば、商品企画で案Aと案Bを比較し、無料の代替手段が強いことを理由に案Aを見送ったとします。

結論だけを「案Aは却下」と記録しても、後から別のAIがその理由を知らずに案Aを再提案するかもしれません。

そこで、次のように残します。

- **判断**：案Aは現時点では採用しない
- **理由**：無料の代替手段との差別化が弱い
- **再検討の条件**：有料でも選ばれる独自価値が確認できた場合

こうしておけば、AIは単に過去の結論に従うのではなく、どんな条件が変われば判断を見直せるのかも理解しやすくなります。

もちろん、記録した判断が常に正しいとは限りません。新しい事実が分かった場合には、再検討する余地を残しておくことが大切です。

## 4. GitHub Discussionsとプロジェクトファイルを組み合わせる

GitHub Discussionsで議論を進めるなら、議論のなかで決まった重要事項を、必要に応じてプロジェクトファイルへ反映します。

役割分担は、例えば次のようになります。

- **Discussions**：議論の経緯や各AIの意見
- **PROJECT.md**：目的と前提
- **DECISIONS.md**：採用した方針と理由
- **NOT_TO_REVISIT.md**：却下済みの案や再議論しない事項
- **STATUS.md**：現在の状況と次の作業

すべてを別ファイルにする必要はありません。情報が少ない段階では一つにまとめ、探しにくくなってきたら分ければ十分です。

注意したいのは、GitHubに記録しただけで、すべてのAIが自動的にその情報を読めるわけではないことです。利用するAIや連携方法に応じて、必要なファイルや要点を会話に渡す作業は残ります。


議論の場そのものを整える方法については、[第1記事「複数AIの会話をGitHub Discussionsに集める方法」](01-github-discussions.md)もあわせてご覧ください。

## 5. AIに渡す情報は、毎回同じ量でなくてよい

毎回すべての資料を貼り付けると、読む側にも渡す側にも負担がかかります。一方、必要な前提が足りなければ、AIは誤った前提で回答する可能性があります。

実務では、次の順に情報を渡すと整理しやすくなります。

1. まず、プロジェクトの目的と現在の状況を伝える
2. 今回の作業に関係する決定事項を渡す
3. 必要な場合だけ、関連する議論や資料を追加する
4. 作業後に新しい決定や状況の変化を記録する

重要なのは、短い説明にすること自体ではありません。**判断に必要な情報を、必要なタイミングで参照できる状態にすること**です。

## 6. 情報整理だけで、すべての問題が解決するわけではない

ファイルを作れば、AIが必ず正しく理解するわけではありません。古い情報を参照することもあれば、記録を読み違えることもあります。情報が増えすぎると、今度は管理自体が負担になります。

そのため、次の点を意識します。

- 決定事項と検討中の案を明確に分ける
- 状況が変わったら、関連ファイルも更新する
- 重要な判断には理由を残す
- AIの回答をそのまま正解とみなさず、人間が確認する
- 最初から完璧な文書構成を目指さない

情報整理の目的は、AIを間違えなくすることではありません。説明のやり直しを減らし、判断や制作に時間を使えるようにすることです。

## 7. まずは、何度も説明していることを一つだけ記録する

最初から立派なナレッジベースを作る必要はありません。

最近の会話を振り返り、「何度も同じ説明をしている」「決めたのに何度も話が戻る」と感じることを一つ選びます。そして、その目的・決定・理由・現在の状況を短いメモにします。

次にAIへ依頼するとき、そのメモを渡してみてください。説明し直す回数が減ったか、回答が作業の続きから始められたかを確認します。

効果があれば、少しずつ記録する情報を増やせばよいのです。

AIを活用するというと、プロンプトの工夫や新しいサービスに目が向きがちです。しかし、継続的な仕事では、AIに何を覚えておいてほしいか、何を参照してほしいかを整理することも重要です。

AIに毎回同じ説明をする時間を、次の一歩を考える時間に変える。そのための小さな情報整理から始めてみてはいかがでしょうか。
