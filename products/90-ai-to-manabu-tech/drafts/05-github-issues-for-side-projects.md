# AIと学ぶ技術｜AIを使った副業のタスクは、GitHub Issuesに書き出して忘れておく

AIを使って副業に挑戦しようとすると、やってみたいことや改善案が次々に出てきます。記事を書く、商品を考える、調査する、ツールを試す。AIに相談するたびに新しい作業が増えることもあります。

ところが、作業が増えるほど「何を先にやるんだっけ」「あのアイデアはどうなった？」「次にどのAIへ何を頼む？」と、頭の中で管理することも増えていきます。

本来は、商品づくりや読者の課題を考えることに頭を使いたいはずです。そこで役立つのが、作業をGitHub Issuesに書き出しておく方法です。

## 頭の中で覚え続けなくていい

私がIssueを使うメリットとして感じているのは、タスクを管理できることだけではありません。**頭の中に置いておかなくてよくなること**です。

気になっていることをIssueに書き出しておけば、今すぐ対応しなくても、後からプロジェクトを見て確認できます。忘れないように何度も思い出す必要が減り、いったん別の作業に集中しやすくなります。

「忘れても、必要になったらここを見ればいい」と思えることには安心感があります。頭の中に未完了の用事を抱え続ける代わりに、次に確認する場所を決めておくわけです。

もちろん、Issueに書いたことが自動的に実行されるわけではありません。定期的に一覧を見て、優先順位を決める必要はあります。それでも、覚えておくことと、実際に作業することを分けられます。

## GitHub Issuesには何を書くのか

Issueは、GitHubで課題や作業項目を記録するための機能です。ソフトウェア開発だけでなく、記事制作や調査、商品企画など、自分のプロジェクトで必要な作業を管理する用途にも使えます。

最初から細かい管理ルールを作る必要はありません。例えば、次の項目を記録します。

- **タイトル**：何をするのか
- **目的・背景**：なぜ必要なのか
- **完了条件**：どこまでできたら終わりなのか
- **状態**：未着手、作業中、完了など
- **次の行動**：次に何をすればよいのか
- **確認事項**：人間が判断すること、未解決の問題

例えば「AI活用の記事を考える」というメモだけでは、後で見たときに何をするつもりだったのか分からなくなるかもしれません。

「複数AIを使った作業管理について、実体験を整理し、読者が再現できる手順と注意点をまとめる。まず過去の作業例を3つ選ぶ」のように書けば、次の一歩を思い出しやすくなります。

完了条件も重要です。「調査する」だけでは、どこで終わればよいのか分かりません。「候補を3つ比較し、採用案と理由を記録する」のように、終わりの状態を具体的にしておくと進めやすくなります。

## 複数のAIに依頼する作業も記録する

AIを複数使う場合は、Issueを作業の受け皿として使えます。

例えば、ある記事を企画するときに、次のように整理できます。

1. 調査担当のAIに、読者の課題や競合を調べてもらう
2. 企画担当のAIに、調査結果をもとに構成案を考えてもらう
3. 批判的な観点を持つAIに、無料で代替できる内容ではないか確認してもらう
4. 人間が結果を比較し、採用する方針を決める

Issueには、担当させるAI、依頼内容、回答の保存先、未解決事項、次の行動を記録します。AIごとに会話の場所が違っても、作業全体の状況をIssueから追いやすくなります。

ただし、GitHub Issuesが各AIに自動で作業を割り当てたり、AI同士で回答を共有したりするわけではありません。AIへの依頼や回答の転記、判断には人間の作業が残ります。自動化されているかのように考えず、まずは管理台帳として使うのが現実的です。

## 副業でAIを使う人と相性がよい理由

副業は、本業や家庭の予定の合間に進める人も多いはずです。使える時間が限られていると、作業そのものだけでなく、「何をするつもりだったか」を思い出すことにも時間を使ってしまいます。

Issueに書き出しておけば、作業を中断しても、戻ってきたときに次の行動を確認できます。思いついたアイデアをその場で実行する必要もありません。まず記録して、あとで優先順位を決めればよいのです。

AIはアイデアを増やしたり、作業の候補を出したりするのが得意な場面があります。一方で、候補が増えすぎると、人間が管理しきれなくなることもあります。Issueは、AIの提案をすべて実行するためではなく、必要なものを選び、今やることと後で考えることを分けるために使えます。

## 最初から完璧なタスク管理にしない

GitHubを使い慣れていない場合、Issueの作成や管理方法を覚えること自体が負担になるかもしれません。すでに使っているメモアプリで十分なら、無理にGitHubへ移す必要はありません。

GitHubでコードや記事、プロジェクト資料を管理しているなら、関連する作業も同じ場所に置けることが利点になります。そうでなければ、使い慣れた道具のほうが続く可能性もあります。

始めるなら、まずは次の3種類だけでも十分です。

- 思いついたアイデアを記録する
- 今やる作業を記録する
- 作業中に分かった課題を記録する

週に一度など、無理のない頻度で一覧を見返し、今取り組むものを選びます。すべてのIssueをすぐに完了させる必要はありません。保留するもの、やらないと決めるものがあっても構いません。

## 頭を空けて、目の前の作業に集中する

タスク管理の目的は、管理表をきれいにすることではありません。やるべきことを忘れないようにしながら、目の前の仕事に集中できる状態をつくることです。

AIを副業に活用すると、思いつくことや試せることが増えます。だからこそ、すべてを覚え続けようとせず、外に書き出しておく仕組みが役立ちます。

まずは、気になっている作業を一つIssueにしてみてください。目的と次の行動を書き、必要になったら一覧から確認する。**覚えておく負担を減らし、頭の中を空けること**から始めてみましょう。
