## 1. 結論

**MAYBE（条件付きGO）**

技術的に「作れる」ことは確認できた。しかし「作れる」と「顧客が1,500円を払う」の間には、まだ埋まっていない溝がある。以下の条件がすべて満たされる場合のみGOに引き上げてよい。

| 条件 | 充足状況 |
|---|---|
| 「1分で変換」を謳わない | 未充足（Gemini案の表現を修正する必要がある） |
| 無料AIとの差別化が「プロンプト」以外にある | 未充足（設計次第） |
| セキュリティ設計が商品に組み込まれている | 未充足（必須） |
| サポート範囲を明確に限定できる | 未充足（必須） |
| 見積は「ドラフト止まり」を徹底する | 設計で対応可能 |

## 2. Gemini案の実装可能性評価

### 2-1. 技術的実現性：高い

Geminiが提案した「乱雑データ → 案件管理・見積ドラフト自動変換キット」は、技術的には **Level 2（テンプレート化）** で実装可能である。API連携もWebアプリも不要。必要なのは以下だけ。

- AIプロンプト（構造化抽出用）
- Googleスプレッドシート or Excel テンプレート
- PDFマニュアル
- サンプルデータ

これらはすべて一人で作成可能であり、特別な開発スキルは不要。

### 2-2. ただし「自動変換」という表現は不正確

Gemini案では「自動変換」と表現されているが、実際の実装は **コピペ＋プロンプト＋手動転記** である。「自動」と呼べるほどの自動化はLevel 2では実現しない。この認識のズレを放置すると、購入後の期待値ギャップが発生する。

### 2-3. 実装可能性の判定

| 項目 | 判定 |
|---|---|
| 一人で作れるか | ✅ 作れる |
| 特殊な技術が必要か | ❌ 不要 |
| 開発期間はどれくらいか | 3〜5営業日（MVP） |
| 技術的障壁はあるか | ほぼない |
| 品質のばらつきは制御できるか | ⚠️ プロンプト品質に大きく依存 |

## 3. 想定ユーザーの実際の利用フロー

以下が現実的な利用フローである。「1分」では絶対に終わらない。

### ステップごとの時間見積もり

| Step | 作業内容 | 推定時間 | 自動化可否 |
|---|---|---|---|
| ① | 商談メモ／音声文字起こしテキストを準備する | 10〜30秒 | ❌ 手動 |
| ② | テキストをコピーする | 5秒 | ❌ 手動 |
| ③ | AIチャット（ChatGPT/Claude等）にプロンプト＋テキストを貼り付ける | 10秒 | ❌ 手動 |
| ④ | AIが構造化情報を出力する（待機） | 15〜30秒 | ⚠️ AI処理 |
| ⑤ | AI出力を確認し、明らかな誤りを修正する | 30〜60秒 | ❌ 人間必須 |
| ⑥ | 構造化されたテキストをコピーする | 5秒 | ❌ 手動 |
| ⑦ | Googleスプレッドシートの該当シートに貼り付ける | 10〜15秒 | ❌ 手動 |
| ⑧ | シート上で案件情報を確認・補完する | 30〜60秒 | ❌ 人間必須 |
| ⑨ | 見積ドラフトシートに必要項目を転記 or 確認する | 30〜60秒 | ❌ 人間必須 |
| ⑩ | 見積内容を最終確認し、金額・条件を確定する | 60〜120秒 | ❌ 人間必須（必須） |

**合計：約4〜7分**（慣れた場合）

初回利用時はプロンプトの使い方を確認しながら進めるため **10〜15分** はかかる。

### 「1分でできるのか？」への回答

**できない。**

「1分」を謳うと、購入者は「1分かからなかった」と不満を持つ。実際に短縮できるのは「30〜60分 → 4〜7分」であり、これを正直に伝えるべきである。

推奨表現：

> 「商談後のメモ整理・CRM転記・見積下書きを、**数分**に短縮するテンプレートキット」

## 5. 技術構成

### 5-1. 採用する技術レベル

**Level 2：テンプレート化**

| レベル | 内容 | 採用可否 | 理由 |
|---|---|---|---|
| Level 1：完全手動 | ユーザーが自由にAIに聞く | ❌ | 商品として成立しない |
| **Level 2：テンプレート化** | **決められたプロンプト＋シート** | **✅ 採用** | **低コスト・低リスク・一人で運用可能** |
| Level 3：シート連携 | Apps Script等でAI出力を自動取込 | ⚠️ 将来拡張 | MVPでは複雑すぎる |
| Level 4：API連携 | AI APIで自動処理 | ❌ | API費用・運用コストが過大 |
| Level 5：Webアプリ | 入力→自動出力のWebサービス | ❌ | 開発コストが過大 |

### 5-2. 使用するサービス（すべて無料 or 既存）

| サービス | 用途 | 費用 |
|---|---|---|
| ChatGPT（無料版）or Claude（無料版） | AI処理 | ¥0 |
| Googleスプレッドシート | テンプレート提供 | ¥0 |
| note | 販売チャネル | ¥0（販売手数料のみ） |
| Googleドライブ | ファイル配布 | ¥0 |
| Canva（無料版）or Google Docs | PDFマニュアル作成 | ¥0 |

### 5-3. 採用しない技術

| 技術 | 不採用理由 |
|---|---|
| OpenAI API | API費用が発生。購入者ごとのAPI管理が困難 |
| Google Apps Script | 環境依存エラーのリスク。サポート負荷増大 |
| Excel VBA / マクロ | セキュリティ警告・環境依存の問題が多発する |
| Python / プログラミング | 購入者が使えるとは限らない |
| 外部SaaS（Notion, Zapier等） | 有料プランが必要になる可能性がある |

## 6. 自動化できる部分

正直に言えば、Level 2で「自動化」と呼べる部分は限定的である。

| 作業 | 自動化可否 | 説明 |
|---|---|---|
| 乱雑テキストからの情報抽出 | ⚠️ 半自動 | AIが抽出するが、人間が確認・修正する必要がある |
| 出力フォーマットの統一 | ✅ 自動 | プロンプトで出力形式を固定できる |
| 案件管理シートへの転記 | ❌ 手動 | コピペが必要 |
| 見積金額の算出 | ❌ 手動 | AIに自動確定させてはいけない |
| タスク抽出 | ⚠️ 半自動 | AIが抽出するが、優先順位は人間が判断 |
| 見積書のフォーマット整形 | ⚠️ 半自動 | テンプレートがあるが、内容は人間が確認 |

**自動化率：体感で約30〜40%。** 残りは人間の手作業である。

| 作業 | なぜ人間がやるべきか |

## 11. サポート負荷

### 11-1. 想定される問い合わせ

| 問い合わせ内容 | 想定頻度 | 対応難易度 | 対応方針 |
|---|---|---|---|
| 「スプレッドシートが開けない」 | 中 | 低 | FAQで対処。ダウンロード手順を明記 |
| 「AIの出力がサンプルと違う」 | 高 | 中 | 入力データの違いを説明。FAQで対処 |
| 「自分の業務に合わない」 | 中 | 高 | ⚠️ 危険。個別カスタマイズには応じない |
| 「プロンプトがうまく動かない」 | 中 | 中 | AIモデル・プランの違いを説明 |
| 「見積計算が合わない」 | 低 | 高 | ⚠️ 見積はドラフト止まり。計算保証はしない |
| 「セキュリティが心配」 | 中 | 中 | セキュリティ注意書きを案内 |

### 11-2. サポート範囲の明確化（必須）

商品ページに以下を明記する：

> **サポート範囲：** 本キットの使い方に関する質問のみ。
> **サポート対象外：** 個別業務へのカスタマイズ、AIサービスの操作指導、Excel/スプレッドシートの基本操作、見積内容の妥当性判断。

### 11-3. 一人運営での対応可否

**条件付きで対応可能。**

- FAQを充実させれば、問い合わせの70〜80%は自己解決できる
- 個別カスタマイズ要求に「ノー」と言えるなら、一人でも回せる
- 逆に、カスタマイズ要求に応じ始めると破綻する

**最大のリスクは「個別カスタマイズ要求」である。**

## 12. セキュリティ・個人情報リスク

### 12-1. リスクの重大度：高い

商談メモには以下が含まれる可能性が高い。

- 顧客名・会社名
- メールアドレス・電話番号
- 金額・見積条件
- 契約内容・秘密情報
- 競合情報

### 12-2. 無料AIへの入力リスク

ChatGPT無料版・Claude無料版は、入力データがモデルの学習に使用される可能性がある（設定による）。顧客の秘密情報を無料AIに入力することは、**情報漏洩リスク**を伴う。

### 12-3. 商品に組み込むべきセキュリティ設計

| 対策 | 内容 | 優先度 |
|---|---|---|
| 匿名化ガイドの同梱 | 「会社名→A社」「氏名→担当者B」に置き換える手順 | ★★★ 必須 |
| ダミーデータでの練習推奨 | 初回はサンプルデータで練習するよう明記 | ★★★ 必須 |
| 秘密情報の入力禁止を明記 | 機密情報・個人情報はマスキングするよう注意書き | ★★★ 必須 |
| AIサービスの設定確認を促す | ChatGPTの「データ共有をオフにする」手順を記載 | ★★ 推奨 |
| 利用者の自己責任を明記 | データ取扱いの最終責任は利用者にあり | ★★★ 必須 |

### 12-4. 法的・規約上の確認が必要な事項

- AIサービス各社の利用規約（データ取扱い条項）→ **確認が必要**
- 個人情報の保護に関する法律（個人情報保護法）→ **確認が必要**
- 企業利用の場合の社内セキュリティポリシー → **利用者自身の確認が必要**

> ⚠️ ここでの法的判断は行わない。「確認が必要」と明示する。

## 13. 見積作成に関するリスク

### 13-1. リスク一覧

| リスク | 影響度 | 対策 |
|---|---|---|
| AIが金額を誤って抽出する | 高 | 人間が必ず確認する |
| 数量の取り違え | 高 | 人間が必ず確認する |
| 税計算のミス | 中 | シートに税計算式を入れるが、最終確認は人間 |
| 条件の漏れ（納期・支払条件等） | 高 | チェックリストをテンプレートに組み込む |
| 案件情報の誤認（別案件の情報混入） | 高 | 1回のAI処理は1案件のみと制限する |

### 13-2. 設計原則

**AIが見積を「自動確定」する設計は絶対に採用しない。**

> AIの役割：**見積ドラフトのたたき台を作る**
> 人間の役割：**内容を確認し、金額・条件を確定する**

この原則を商品ページ・マニュアル・プロンプトすべてに明記する。

## 14. 無料AIによる代替リスク

### 14-1. 無料AIで再現できること

顧客がChatGPTやClaudeに以下のように入力すれば、それなりの結果が得られる。

> 「この商談メモから、案件名・顧客名・要望内容・次回アクション・見積に必要な情報を抽出して」

これだけで、構造化された情報が出力される。つまり、**プロンプト単体の価値は極めて低い。**

### 14-2. 無料AIで再現しにくいこと

| 要素 | 無料AIで再現できるか | 商品としての価値 |
|---|---|---|
| プロンプトそのもの | ✅ 再現可能 | 低い |
| 出力フォーマットの統一 | ⚠️ 毎回指示が必要 | 中（時短） |
| スプレッドシートテンプレート | ⚠️ 自作は可能だが面倒 | 中 |
| 見積ドラフトの定型フォーマット | ⚠️ 自作は可能だが面倒 | 中 |
| サンプルデータ（入力例・出力例） | ❌ 自分で作るのは面倒 | 中〜高 |
| エラー事例と対処法 | ❌ 経験が必要 | 中〜高 |
| セキュリティ設計（匿名化手順） | ❌ 専門知識が必要 | 高 |
| 「この順番でやればよい」という手順書 | ❌ 自分で組み立てるのは面倒 | 中〜高 |

### 14-3. 結論

**「プロンプト」だけでは商品にならない。** 有料価値が生まれるのは、以下のパッケージが揃ったときである。

> プロンプト ＋ シートテンプレート ＋ サンプルデータ ＋ エラー事例 ＋ セキュリティガイド ＋ 手順書

この「一式揃っていること」が、1,000〜2,000円の根拠になり得る。

## 15. 「なぜ1,000〜2,000円払うのか」への回答

### 15-1. 顧客が払う理由（仮説）

| 理由 | 説明 |
|---|---|
| セットアップの時短 | 自分でプロンプトを設計し、シートを作り、フォーマットを整えるのに3〜5時間かかる。このキットを使えば30分で使い始められる |
| 失敗の回避 | 「どんなプロンプトを書けばいいかわからない」「どんなフォーマットがいいかわからない」という試行錯誤を省略できる |
| 運用の再現性 | 毎回同じ品質で案件情報を抽出できる。属人的なスキルに依存しない |
| セキュリティの安心感 | 匿名化手順や注意点があらかじめ整理されている |

### 15-2. 顧客が払わない理由（反論）

| 理由 | 説明 |
|---|---|
| 無料AIで十分 | 「自分でChatGPTに聞けばできる」 |
| 無料で類似情報がある | noteやSNSで無料のプロンプト集が大量にある |
| 効果が不確実 | 「本当に自分の業務に合うかわからない」 |
| 価格の心理的壁 | 「コピペ作業に1,500円は高い」と感じる可能性 |

### 15-3. 判定

**払う理由は存在するが、弱い。**

「3〜5時間のセットアップ時間を30分に短縮する」という価値は、時給換算すれば1,500円以上になる。しかし、顧客がその価値を「購入前に実感できるか」が問題である。

**対策：** note記事（販売ページ）で、サンプルの入力→出力を具体的に示し、「これがあなたの商談メモでできる」とイメージさせることが不可欠。

## 17. 最大の問題点

### 問題①：「自動化」の実態がコピペである

Gemini案の「自動変換」という表現と、実際のコピペ作業の間に大きなギャップがある。このギャップを正直に伝えないと、購入後の不満・返金要求につながる。

### 問題②：無料AIとの差別化が薄い

プロンプト＋テンプレートの組み合わせは、無料AIを30分使えば自分でも作れる。この「30分の差」に1,500円を払う人がどれだけいるか。

### 問題③：セキュリティリスクが商品価値を毀損する可能性がある

「商談メモをAIに入力する」という行為自体に抵抗感を持つ顧客が多い場合、商品の利用シーンが限定される。

### 問題④：個別カスタマイズの圧力

「自分の業務に合わせたい」という要求が来た場合、一人運営では対応しきれない。これを明確に断る設計が必要。

## 18. GO / MAYBE / NO-GOの最終判定

### 判定：MAYBE（条件付きGO）

**MAYBEの理由：**

技術的に作れることは確認できた。初期費用ゼロ、維持費ゼロ、一人で作れる。しかし、以下の条件が満たされなければ商品として成立しない。

### GOに引き上げるための必須条件

| # | 条件 | 現状 |
|---|---|---|
| 1 | 「1分で変換」を謳わない。「数分で短縮」と正直に伝える | 未対応 → 必須 |
| 2 | プロンプトだけでなく「一式パッケージ」として設計する | 未対応 → 必須 |
| 3 | セキュリティガイド（匿名化手順）を商品に同梱する | 未対応 → 必須 |
| 4 | 見積は「ドラフト止まり」とし、自動確定しない | 設計で対応可能 |
| 5 | サポート範囲を明確に限定し、個別カスタマイズには応じない | 未対応 → 必須 |
| 6 | note記事で「自分の商談メモでこうなる」と具体的にイメージさせる | 未対応 → 必須 |
| 7 | 価格を¥980〜1,280に抑え、試行錯誤の心理的ハードルを下げる | 要検討 |

### NO-GOになる条件

以下に一つでも該当すればNO-GOとする：

- 個別カスタマイズが前提になる場合
- 有料APIやSaaSが必須になる場合
- セキュリティリスクを無視して「とにかくAIに入れろ」という設計になる場合
- サポートが一人では回せないと判断された場合

## 19. 次のKimiに検証してほしい論点

Kimiには「全体情報整理・競合比較・経営判断」の観点から、以下を検証してほしい。

### 論点①：競合の具体的価格帯と販売実績

note上で「AI × 業務効率化 × テンプレート」で販売されている商品の実際の価格帯と、販売数（もし推定可能なら）を調査してほしい。¥1,000〜2,000円の価格帯で実際に売れている事例があるか。

### 論点②：「一式パッケージ」の差別化が競合に対して有効か

プロンプト集・テンプレート集は大量に存在する。「プロンプト＋シート＋サンプル＋セキュリティガイド」の一式パッケージが、既存の競合に対して本当に差別化になるか。

### 論点③：ターゲットの絞り込み

Gemini案ではターゲットが「フリーランス・個人事業主・中小企業の営業担当者」と幅広い。これをさらに絞るべきか（例：「ITフリーランスの商談メモ」に特化）。絞った方が刺さるが、市場が小さくなる。経営判断としてどちらがよいか。

### 論点④：価格の妥当性

¥980、¥1,280、¥1,500、¥1,980のいずれが適切か。無料AIとの代替性を考慮したとき、この価格帯で「衝動買い」を期待できるか。それとも「検討して買う」価格帯か。

### 論点⑤：この商品を「作らない」という判断

もし競合調査の結果、類似商品が大量にあり、かつ販売実績が芳しくない場合、「この商品は作らない」という判断も選択肢に入れるべきか。その場合、Product 4の実験自体をどう意味づけるか。
