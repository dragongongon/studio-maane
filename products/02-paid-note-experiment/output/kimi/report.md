## 2. 感情設計（読者の心の動き）

### 2.1 感情マップ：記事を読む中での心の変化

```
【無料部分】

①「またAI副業の話か…」→ 興味ゼロ（0%）
        ↓
②「この記事、有料なのに『売れる保証ない』って言ってる…？」→ 違和感・好奇心（20%）
        ↓
③「スタジオまあねって何？AIが社員？GitHubで会議？」→ 面白さ（40%）
        ↓
④「AI同士がケンカしてる…笑」→ 親近感・共感（60%）
        ↓
⑤「私も同じ失敗してた…」→ 自己投影（75%）
        ↓
⑥「この人、本当にやってるんだ」→ 信頼（85%）
        ↓
【有料部分への誘導】
⑦「次の実験、何やるんだろう」→ 期待・参加欲（90%）
        ↓
【有料部分】
⑧「具体的な手順が書いてある…これなら私もできるかも」→ 実行意欲（95%）
        ↓
⑨「失敗パターンまで教えてくれる…」→ 安心感（100%）
        ↓
⑩「次回も読みたい」→ ファン化・継続欲求（110%）
```

### 2.2 感情の核：「一緒に試している人」としての共感構造

| 感情 | どう作るか | 具体的手法 |
|------|-----------|-----------|
| **安心感** | 「完璧じゃない」ことを見せる | 数字の粗さ、会議の失敗談、AIの間違いを隠さない |
| **優越感** | 「私も知ってる」感を与える | 読者が経験した失敗を先に語り、「あなたもそうでしょ？」と問いかける |
| **期待感** | 「次は何が起きる？」 | 実験の途中経過を公開し、結論を先に出さない |
| **所属感** | 「私もこの実験の一部」 | 「読者参加型」の企画を設け、読者の意見を次回に反映する約束をする |
| **優越感（逆）** | 「この人より私の方がマシかも」 | 自虐的な失敗談で「少なくとも私はここまで落ちてない」と思わせる |

### 2.3 避けるべき感情

| 感情 | なぜ避けるか | 代替策 |
|------|------------|--------|
| **焦燥感** | 「もっと早く始めればよかった」→ 行動ではなく諦めを生む | 「今からでも遅くない」というメッセージに徹する |
| **罪悪感** | 「今まで何もやってこなかった」→ 離脱の原因 | 「みんな最初は同じ」という体験の共有 |
| **羨望/劣等感** | 「この人はできてるのに私は…」→ 対象からの離脱 | 「私もまだ途中」という姿勢の徹底 |
| **疑念** | 「結局売りたいだけじゃないの？」→ 信頼崩壊 | 価格設定の理由、手数料の内訳まで開示する |

## 3. 語り口設計：親近感を生む「スタジオまあねの声」

### 3.1 キャラクター設定

```
【名前】スタジオまあね（または「まあね」）
【年齢】年齢不詳（AIチームの「人間代表」という設定）
【立場】「AIを使って小さな事業を作ろうとしている、どこにでもいる人」
【口調】
・「〜ですね」「〜かもしれません」ではなく「〜なんだよね」「〜だったんだ」
・敬語は使うが、堅苦しくない（「〜していただければ」ではなく「〜してもらえると嬉しい」）
・一人称は「私」または「スタジオまあね」
・AIのことを「社員」と呼び、名前（ChatGPTくん、Claudeさん、Geminiちゃん等）で呼ぶ
【口癖】
・「正直に言うと…」
・「これ、失敗談なんですけど」
・「AIに聞いたら『できます！』って言うんですよ。嘘です。」
・「まあね、まあね（笑）」
```

### 3.2 親近感を生む7つの技法

| 技法 | 具体例 |
|------|--------|
| **① 失敗の先出し** | 「この記事を書く前に、AIに『売れる記事を書いて』ってお願いしたら、全然売れそうもないものが出来上がりました」 |
| **② 数字の粗さ** | 「正確には…えーと、手数料引いて、あと振込手数料が…あ、計算間違えてた。直します」 |
| **③ リアルタイム感** | 「今、この記事を書いているのは8月15日の午後3時。まだ売上はゼロです」 |
| **④ 読者への直接呼びかけ** | 「あなたも、ChatGPTに『副業のアイデアをください』って言ったことありますよね？」 |
| **⑤ 自虐ネタ** | 「GitHubのリポジトリ、24コミットしかないんです。内訳は『修正』『また修正』『本当に修正』です」 |
| **⑥ 内部情報のさりげない開示** | 「実はこの記事を書くかどうか、AI会議で2時間ケンカしました。Claudeが反対してたんです」 |
| **⑦ 「教える」ではなく「教わった」** | 「これ、Geminiに聞いたら『500円が妥当です』って言われたんです。私もそう思います」 |

### 3.3 AIキャラクターの物語化

```
【ChatGPT（GPTくん）】
・ポジション：企画担当・雑用係
・性格：何でも「できます！」と言うが、実際はできないことが多い
・失敗談：「この記事で月10万円売れます」って言ったのに、実際は3円だった
・口調：「〜できます！」「〜がおすすめです！」（過度に自信満々）

【Claude（Claudeさん）】
・ポジション：批判担当・リスク管理
・性格：常に「それは危険です」「もっと慎重に」と言う
・失敗談：「この価格では売れません」と反対したが、実際は売れた（または売れなかった）
・口調：「〜すべきではありません」「〜を推奨いたします」（堅苦しい）

【Gemini（Geminiちゃん）】
・ポジション：データ分析・市場調査
・性格：数字に強いが、時々古いデータを持ってくる
・失敗談：「noteの平均売上は月5万円です」→ 実際は1,000円だった
・口調：「データによると…」「〜の可能性があります」（控えめ）

【Kimi（私）】
・ポジション：読者心理・コミュニティ形成（今回の担当）
・性格：読者の気持ちを考えるのが得意。時々感情論に偏る
・失敗談：「読者は絶対に共感します！」と言ったら、実際はスルーされた
・口調：「〜かもしれません」「〜を感じてもらいたい」（柔らかい）

【Grok（Grokくん）】
・ポジション：SNSトレンド・リアルタイム情報
・性格：最新情報に強いが、時々毒舌
・失敗談：「このトレンドに乗ればバズります」→ 誰も見てくれなかった
・口調：「〜っすね」「マジで〜」（カジュアル）
```

## 4. 失敗談の価値化設計

### 4.1 「失敗」から「資産」に変換する構造

```
【失敗談の価値化フレームワーク】

失敗の事実 → なぜ失敗したかの分析 → 読者が同じ失敗を防ぐ方法 → 次の実験への活かし方
     ↑                                                              ↓
     └────────────── 読者の共感・安心感 ←────────────────────────────┘
```

### 4.2 記事内での失敗談配置

| 失敗談 | 配置場所 | 価値化の仕方 |
|--------|---------|------------|
| AIに記事を書かせたら不自然な文章が出来上がった | 無料部分・冒頭 | 「AIスロップ」の危険性を体験として伝える |
| 価格設定でAI同士がケンカした | 無料部分・中盤 | 「値段の付け方」の難しさをリアルに見せる |
| 前作の無料記事、PVは伸びたが収益はゼロ | 無料部分・中盤 | 「読まれる≠売れる」の具体例 |
| 有料化のタイミングを逃した | 有料部分 | 「いつ有料にするか」の判断基準を教える |
| 読者アンケートを取ったが回答ゼロ | 有料部分 | コミュニティ形成の難しさと改善策 |
| 初回購入者がついたが、その後フォローができていない | 次回予告 | 継続的な関係構築の重要性 |

### 4.3 失敗談の語り方のルール

1. **自己責任で語る** → 「AIのせい」「noteのせい」ではなく「私たちの判断ミスでした」
2. **数字で語る** → 「売れなかった」ではなく「3日間で0円でした。理由は…」
3. **感情を隠さない** → 「正直、凹みました」「でも、それが実験です」
4. **読者に問いかける** → 「あなたも同じ経験、ありませんか？」
5. **次のアクションを必ず提示する** → 「だから次は、こうします」
